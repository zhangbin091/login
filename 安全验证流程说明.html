1触发链路：从点击「登录」到弹出验证

核心结论：安全验证是在账密接口之前触发的。验证没通过，登录请求根本不会发出。

为什么顺序不能反

如果把 geetest.verify() 放在账密校验之后，攻击者可以直接裸调登录接口绕过人机验证。 放在前面，配合服务端的二次复核（见第 5 节），才能同时挡住「脚本刷登录」和「篡改前端跳过验证」。

✓ 为什么不做「探活」

早先的写法是：先向 /register 发一次请求探活，探活失败就降级到本地模拟。 但极验 v4 的 /register 是给「私有化部署 / 宕机兜底」准备的可选接口， SaaS 账号通常直接返回 403；v4 标准接入只需要服务端实现 /validate， 浏览器里的 gt4.js 自己会完成 register。 把探活当模式开关，结果就是「真实极验永远不生效」，与降级的初衷正好相反。详见第 6 节。

3真实模式：弹窗是怎么被加载出来的

gt4.js 不在 npm 依赖里，是运行时从极验 CDN 动态拉取的。整个弹窗由极验 SDK 自己创建。

四个阶段

阶段代码发生了什么
① 加载 SDK 19-39 动态创建 <script id="geetest-gt4-js" src="https://static.geetest.com/v4/gt4.js" async> 插入 <head>，靠 onload 继续。已加载过就复用，不重复插入。
② 初始化 59-66 调 initGeetest4()。SDK 内部自己向极验服务器发起 register（实测是 gcaptcha4.geetest.com/load?captcha_id=…）——这才是 v4 真实接入中 register 发生的唯一场所，服务端不参与——然后构建浮层 DOM。此时弹窗还没显示。
③ 显示弹窗 71-73 onReady 回调里调 showCaptcha() —— 这一行才是弹窗出现在屏幕上的时刻。只初始化不调它，界面什么都不会发生。
④ 取回结果 74-77 onSuccess 里 getValidate() 返回 { lot_number, captcha_output, pass_token, gen_time }，Promise resolve，控制权交回 login.js:65。
为什么需要 destroyActive()

product: 'bind' 的浮层 DOM 由极验 SDK 直接挂在 document.body 下， 不在 Vue 组件的 $el 子树里。Vue 销毁组件时管不到它，所以 geetest.js:41-48 用 destroyActive() 在每次 verify() 开头手动兜底销毁， 避免出异常后留下一个关不掉的浮层挡住页面。

6一次真实排障：配了 KEY 却仍走模拟（已修复）

⚠ 现象

在 config/index.js 填入 captchaId / captchaKey 后实测： 

POST /api/geetest/register
→ { "mode": "mock", "lotNumber": "50e57e19-...", "degraded": true }

单独复现 prepare() 里那个 register 请求，极验返回 HTTP 403， 于是命中降级分支，前端被强制退回本地模拟滑块，真实极验根本不会加载。

排查：403 不等于 KEY 无效

换一个接口打同一对 id/key，结果完全不同： 

POST https://gcaptcha4.geetest.com/validate?captcha_id=…
  （参数是伪造的）
→ 200 { "result": "fail", "reason": "pass_token error", "status": "success" }

status: "success" 说明服务端已经受理并开始校验， fail 只是因为参数是假的 —— 这证明 id/key 这一对是有效的， 403 并不是鉴权失败。

用 CDP 抓真实浏览器的网络请求，看到 gt4.js 实际访问的是： 

GET https://gcaptcha4.geetest.com/load?captcha_id=3fcca12f…  → 200

根因：把探活当成了模式开关

极验 v4 的 /register 是给「私有化部署 / 宕机兜底」准备的可选接口， SaaS 账号通常直接 403。v4 标准接入只需要服务端实现 /validate， register 由浏览器里的 gt4.js 自己完成（走的是 /load）。

老代码却拿 register 的返回值当模式开关，于是只要这个可选接口不可用， 真实极验就永远不生效 —— 与「探活失败才降级」的初衷正好相反。

✓ 已采用的改法

删掉 register 探活，模式只由 isRealMode() 决定： 配了 id/key 就是 gt4，没配（或设了 GEETEST_DISABLED=1）就是 mock。 改动集中在 services/geetest.js:29-60，同时删掉了 REGISTER_API 常量。

✓ 修复后验证

真实模式：gt4.js 200、/load 200、弹层渲染 49 个 DOM 节点、 initGeetest4 为 function，无 JS 异常。

模拟模式回归（$env:GEETEST_DISABLED=1）： 浏览器 E2E 全流程通过，冒烟测试 18/18。

唯一未自动化的环节：真实滑块的拖动。合成事件无法通过极验的防机器人判定 （这正是它存在的意义），最后一步需要在真实浏览器里由人工完成。
